- 상태: Confirmed (2026-11-03, 인터뷰 Standard)

- 저장소: https://github.com/Softbank-Hackathon-2026-Team-Echo/echo-demo-app (공개, main 단일 + 기능 브랜치, PR 필수)
- 담당: 김지민

## 1. 목적

이전(AWS 도쿄 → GCP 서울) 시연에서 옮겨지는 **고객 앱 역할**을 한다. 지금은 echo-was 자신을 서비스로 등록해 두어 "플랫폼이 플랫폼을 옮기는" 그림이 된다. 이 앱이 그 자리를 대신한다.

- 순번 쓰기로 이전 중 데이터 손실 0(누락 0·중복 0)을 보여 준다(원장 F8, NFR-03).
- 화면 하나가 반분할 시연의 오른쪽 화면이 된다: 지금 순번 + 응답한 환경.

## 2. 확인된 사실 (조사)

| 사실 | 출처 |
|---|---|
| 데이터 이전은 PostgreSQL 논리 복제 + PgBouncer(transaction 모드) 컷오버. 앱은 **PgBouncer로만** DB에 붙는다 | echo-infra ADR-0004, `specs/infra-7-…` |
| PoC 표: `demo.seq_write(id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, n bigint NOT NULL UNIQUE, wrote_at timestamptz NOT NULL DEFAULT now())`, n = `max(n)+1`. 대조 SQL(`verify.sh`)은 이 표의 `n`으로 누락·중복을 센다 | echo-infra PR #18 `replication/sql/schema.sql`, `scripts/verify.sh` |
| 논리 복제는 시퀀스·DDL을 옮기지 않는다 → 스키마는 대상에 먼저 만들고, 컷오버 때 시퀀스를 맞춘다(#7 몫) | ADR-0004 |
| echo-was 서비스 기본값: `containerPort` 8080, `healthCheckPath` `/healthz`. 빌드 실행기는 저장소 주소 + 커밋으로 이미지를 만든다(공개 저장소면 토큰 불필요) | echo-was `docs/api/services.md`, `docs/executors.md` |
| 진입점 부하(k6 loadgen)는 `GET {TARGET_PATH}`를 50 rps로 보내는 **읽기** 트래픽이다(이전 판정용) | echo-infra `entrypoint/loadgen/loadgen.js` |
| 환경 이름 `aws-tokyo`·`gcp-seoul`(+ 온프레) | ADR-0004, SPEC infra-7 |

## 3. 결정

| ID | 결정 | 출처 |
|---|---|---|
| D-1 | 순번 쓰기는 **화면(브라우저)만** 한다. [쓰기 시작]을 누른 뒤 주기적으로 보낸다. 자동 부하(loadgen)는 쓰기를 하지 않는다(읽기 트래픽만, 별개) | 사용자 |
| D-2 | 저장소 이름 `echo-demo-app`, 해커톤 조직 **공개** 저장소. 비밀값 0건 | 사용자 · 이슈 댓글 |
| AD-1 | 번호는 **서버가 매긴다**(PoC와 같은 `max(n)+1`). 한 트랜잭션 안에서 `pg_advisory_xact_lock`으로 직렬화해 동시 요청에도 번호가 겹치지 않게 한다(PgBouncer transaction 모드에서 트랜잭션 잠금은 안전). 쓴 환경 이름 칸 `written_env`를 더한다 | AI-default |
| AD-2 | 쓰기는 [쓰기 시작]을 눌러야 시작한다(화면을 여는 것만으로는 쓰지 않는다 — 심사위원·팀원이 열 때마다 번호가 쌓이지 않게) | AI-default |
| AD-3 | 화면은 "확인 받은 마지막 번호"(브라우저가 201 응답으로 받은 최대 n)를 기억하고 장부의 최대 번호와 나란히 보인다. 장부 최대 < 확인 받은 번호면 "꼬리 손실 의심"을 표시한다(재난처럼 쓰기 정지 없이 끊긴 경우를 드러냄) | AI-default |
| AD-4 | 스택: Python 3.13 + FastAPI + psycopg 3(+ psycopg_pool, `prepare_threshold=None` — PgBouncer transaction 모드에서 서버 측 prepared statement를 쓰지 않는다) + uv. 화면은 앱이 내주는 정적 HTML·CSS·JS 한 장(빌드 단계 없음) | AI-default (echo-was와 같은 언어) |
| AD-5 | 환경 이름은 환경 변수 `ECHO_ENVIRONMENT`로 받는다. 없으면 `unknown`. 실제 주입은 echo-was 배포 실행기 몫(후속) | AI-default |
| AD-6 | 스키마는 앱 시작 때 `CREATE SCHEMA/TABLE IF NOT EXISTS` + `ADD COLUMN IF NOT EXISTS`로 맞춘다(`AUTO_MIGRATE`, 기본 true). 같은 내용을 `sql/schema.sql`로도 둔다 — 복제 대상 DB에 먼저 적용하는 용도. Alembic은 쓰지 않는다(표 1개) | AI-default |
| AD-7 | 초기화(장부 비우기) API는 만들지 않는다 — 공개 인터넷 앱이라 누구나 지울 수 있게 된다. README에 `psql`/스크립트로 비우는 방법만 적는다 | AI-default |
| AD-8 | 이미지 레지스트리 게시(GHCR 등)·k8s 매니페스트는 이번 범위가 아니다. 빌드·배포는 Echo 플랫폼(echo-was 실행기·인프라 3)이 한다 | AI-default |

## 4. 인터페이스

모든 JSON은 camelCase. 인증 없음(공개 시연 앱).

| 메서드·경로 | 동작 | 응답 |
|---|---|---|
| `GET /healthz` | 프로세스 생존만 본다. **DB를 보지 않는다**(컷오버 중 PgBouncer PAUSE 동안 헬스체크가 실패해 파드가 재시작되지 않게) | 200 `{"status":"ok"}` |
| `GET /readyz` | `SELECT 1`(제한 2초) | 200 `{"status":"ready"}` / 503 `{"status":"unavailable"}` |
| `GET /api/info` | 응답한 환경 정보 | 200 `{"environment":"aws-tokyo","hostname":"<파드 이름>","version":"<APP_VERSION 또는 dev>"}` |
| `POST /api/writes` | 본문 없음. 트랜잭션: `SELECT pg_advisory_xact_lock(<상수>)` → `INSERT INTO demo.seq_write(n, written_env) SELECT COALESCE(max(n),0)+1, $env FROM demo.seq_write RETURNING n, wrote_at` | 201 `{"n":412,"environment":"aws-tokyo","hostname":"…","wroteAt":"…"}` / DB 실패 503 `{"error":"DB_UNAVAILABLE"}` |
| `GET /api/writes/summary` | 장부 대조 | 200 아래 형식 |
| `GET /` | 화면 | HTML |

`summary` 형식:

```json
{
  "environment": "gcp-seoul",
  "total": 500, "distinct": 500, "minN": 1, "maxN": 500,
  "missing": 0, "duplicates": 0,
  "byEnvironment": [
    {"environment": "aws-tokyo", "count": 300, "minN": 1, "maxN": 300},
    {"environment": "gcp-seoul", "count": 200, "minN": 301, "maxN": 500}
  ],
  "recent": [{"n": 500, "environment": "gcp-seoul", "wroteAt": "…"}]
}
```

- `missing` = `(maxN − minN + 1) − distinct`(행이 없으면 0), `duplicates` = `total − distinct`. PoC `verify.sh`와 같은 뜻이다(`n`이 UNIQUE라 duplicates는 보통 0 — 계산은 남긴다).
- `recent`는 최근 10건, n 내림차순. `byEnvironment`는 minN 오름차순.

## 5. 저장 구조

```sql
CREATE SCHEMA IF NOT EXISTS demo;
CREATE TABLE IF NOT EXISTS demo.seq_write (
  id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  n           bigint NOT NULL UNIQUE,
  wrote_at    timestamptz NOT NULL DEFAULT now(),
  written_env text NOT NULL DEFAULT 'unknown'
);
ALTER TABLE demo.seq_write ADD COLUMN IF NOT EXISTS written_env text NOT NULL DEFAULT 'unknown';
```

PoC 표에 칸 하나(`written_env`, 기본값 있음)만 더한다. PoC의 `writer.sh`·`verify.sh`·publication은 그대로 동작한다. `id`는 `BY DEFAULT`(논리 복제가 명시 id를 넣을 수 있어야 함)를 유지한다.

## 6. 화면 (`GET /`)

- 반분할 오른쪽(약 960px 폭 프로젝터)에서 읽히게 큰 글씨. 한국어.
- 위: **지금 순번**(가장 최근 201 응답의 n, 아주 크게) + **응답 환경 배지**(이름별 색: `aws-*` 주황, `gcp-*` 파랑, `onprem*` 초록, 그 밖 회색. 사람이 읽는 이름: `aws-tokyo` → "AWS 도쿄", `gcp-seoul` → "GCP 서울", `onprem*` → "온프레", 그 밖은 원래 이름) + 파드 이름(작게).
- 버튼: [쓰기 시작] / [멈춤]. 쓰기는 **직렬**(응답을 받은 뒤 다음 요청) + 요청 간격 기본 200ms(주소 `?interval=<ms>`로 50~5000 조정). 요청 하나 제한 시간 10초(넘으면 실패로 센다).
- 숫자 줄: 보낸 수 · 성공 · 실패 · 마지막 확인 번호 · 장부 최대 번호 · 누락 · 중복. 응답을 기다리는 중이 1초를 넘으면 "응답 대기 중 N.N초"(컷오버 쓰기 정지가 눈에 보이게).
- 장부 값은 `summary`를 1초마다 읽는다(쓰기와 별도, 쓰기를 멈춰도 계속).
- 꼬리 손실 표시(AD-3): 장부 최대 번호 < 마지막 확인 번호면 빨간 경고 "확인 받은 번호 X가 장부에 없음".
- 환경 띠: 최근 60건 응답을 작은 칸으로 나열해 환경 색으로 칠한다 → 도쿄 → 서울 전환 순간이 색 경계로 보인다. 환경별 건수 표(`byEnvironment`).
- 외부 CDN·폰트·라이브러리를 쓰지 않는다(오프라인·차단 환경에서도 뜨게).

## 7. 실행·설정

| 환경 변수 | 뜻 | 기본 |
|---|---|---|
| `DATABASE_URL` | PostgreSQL(PgBouncer) 접속 문자열 | 필수 |
| `ECHO_ENVIRONMENT` | 응답 환경 이름 | `unknown` |
| `APP_VERSION` | 표시용 버전(커밋 등) | `dev` |
| `AUTO_MIGRATE` | 시작 때 스키마 맞춤 | `true` |
| `PORT` | 듣는 포트 | `8080` |

- DB가 없어도 프로세스는 뜬다(`/healthz` 200, `/readyz` 503, 쓰기 503). 시작 때 스키마 맞춤이 실패하면 로그를 남기고 이후 첫 쓰기 전에 다시 시도한다.
- `Dockerfile`: 루트, 멀티스테이지(uv), 비루트 UID 1001, `EXPOSE 8080`.
- `compose.yaml`(로컬): `postgres:17`(`wal_level=logical`) + PgBouncer(transaction 모드) + 앱. 앱은 PgBouncer로만 붙는다. `docker compose up -d --wait`로 뜨고 `http://localhost:8080`.
- `.env.example`만 커밋. 비밀값 0건.

## 9. 완료 기준

이 PR이 채우는 것(로컬·컨테이너·CI에서 확인):

1. 단순한 웹앱 + PostgreSQL. 데이터 대조용 순번 쓰기 엔드포인트가 있다. (이슈 기준 1)
   - 시험: PgBouncer(transaction 모드)를 거쳐 **동시 50건** `POST /api/writes` → n 1~50, 누락 0·중복 0, 모두 201.
   - 시험: `summary`의 total·missing·duplicates·byEnvironment가 직접 넣은 행(일부러 번호를 비운 행 포함)과 맞다.
2. 공개 GitHub 저장소에 있고 `/healthz`가 응답한다. (이슈 기준 3)
   - 시험: DB가 없을 때도 `/healthz` 200, `/readyz` 503, 쓰기 503.
   - `docker build` 성공, 컨테이너가 `compose up --wait`로 떠서 `curl /healthz` 200.
3. 화면에 지금 순번과 응답한 환경 이름이 보인다. (이슈 기준 4)
   - 로컬 compose에서 `ECHO_ENVIRONMENT=aws-tokyo`로 띄워 [쓰기 시작] → 순번 증가·"AWS 도쿄" 배지 확인(브라우저 스크린샷 1장을 PR 본문 설명에 쓸 수 있게 `docs/screenshot.png`).
4. CI(`test`)가 PR에서 통과한다.

이 PR 뒤에 남는 것(이슈는 열어 둔다):

- 세 환경(AWS 도쿄 / GCP 서울 / 온프레) 배포 — 인프라 2(온프레 k3s)·인프라 3(배포 파이프라인)·echo-was 실제 실행기에 기댄다. 실행기가 `ECHO_ENVIRONMENT`를 넣어야 한다.

## 10. 하지 않는 것

- 인증·요금 제한, 장부 비우기 API, 여러 표·실제 업무 기능.
- 이미지 레지스트리 게시, k8s 매니페스트·Helm, 클라우드 자원.
